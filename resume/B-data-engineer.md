## Опыт работы

### ООО "Цифровые Сервисы" — март 2023 — по настоящее время

**Должность:** Старший разработчик платформы данных

---
Платформа больших данных — корпоративное хранилище данных (КХД) холдинга РЖД, построенное по принципам Data Mesh: больше сотни доменов. Путь данных: источники → Kafka → HDFS → Greenplum, слои от сырых данных до витрин, оркестрация Apache Airflow, трансформации в dbt. Команда разрабатывает платформу, на которой доменные команды строят свои конвейеры данных: фреймворк загрузок и метаданных, права доступа, сервис дата-продуктов.

Разрабатываю ядро платформы, веду задачи от требований и ТЗ до приёмки на стенде. С декабря 2024 — старший разработчик, до этого — разработчик. В команде 8 человек: распределяю задачи бэкенда, провожу код-ревью, был наставником младшего разработчика на испытательном сроке.

Результаты:
• Спроектировал перенос данных и метаданных платформы на новую инфраструктуру заказчика для двух контуров, пром и тест: Greenplum, 1189 топиков Kafka, HDFS, проекты dbt, метаданные сервисов. Определил состав, порядок и способ переноса каждого компонента, подготовил инструкции и скрипты для администратора заказчика. Перенос прошёл с первой попытки и без полной остановки платформы: поступление данных из источников и доступ потребителей к витринам не прерывались.
• Спроектировал и реализовал ролевую модель для совместной работы нескольких проектных команд в одном домене: права и авторство объектов согласованы в Greenplum, фреймворке метаданных, Airflow, сервисе дата-продуктов и dbt, наработки команды переживают перенос между контурами. Написал требования и ТЗ по компонентам, разработал, провёл приёмку релиза.
• Развивал фреймворк загрузок на Airflow: сделал DAG автономными (метаданные хранятся на воркерах, ушли повторяющиеся запросы к БД), добавил 7 типовых шагов-сенсоров (SQL, HTTP, Kafka, внешняя задача, время и другие), которые ждут события без занятого слота воркера и подключения к Greenplum.
• Разбираю инциденты и производительность Greenplum на проде: ресурсные очереди, потеря unlogged-таблиц после рестарта сегмента, коллизии OID, откаты оптимизатора ORCA, замедление после расширения кластера. Подготовил концепты резервного копирования и регламентного обслуживания Greenplum.
• Ускорил веб-интерфейс фреймворка метаданных: основной запрос формы шага — с 5,3 с до 38 мс, в 140 раз.
• Связал сервис дата-продуктов и dbt: права на объекты восстанавливаются после пересоздания моделей dbt, расхождения отслеживаются по хеш-сумме; макрос dbt вызывается после каждого запуска моделей.
• Перевёл функции API метаданных на повторяемые миграции Flyway: правка функции без новой версионной миграции, ревью стало проще.
• Процессы: внедрил журнал архитектурных решений (ADR) и AGENTS.md; перестроил git-workflow — конфликты слияния при релизах исчезли во всех четырёх репозиториях. Выстроил разработку с ИИ-агентом (Claude Code) с доступом к Jira, Confluence и GitLab.
• Передача знаний: курс по dbt Core во внутренней базе знаний; 5 докладов для команды, в том числе об архитектурах данных (Data Lake, Lakehouse, Data Mesh), надёжном Kafka-consumer и работе с персональными данными.

Всего более 100 задач за 3,5 года.

Стек: Python, SQL, PL/pgSQL, Greenplum, PostgreSQL, Apache Airflow, Apache Kafka, HDFS, Apache Spark, dbt, Flyway, Ansible, FastAPI, Docker, GitLab CI, Linux.
